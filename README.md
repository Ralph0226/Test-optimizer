# ITO Waste FJH Indium Recovery - Structure Innovation Optimizer

ITO废料闪蒸焦耳热铟回收 — 梯度浓度反应床与同轴一体化冷凝腔专利技术方案及可视化系统

---

## 项目简介

本项目为"一种基于梯度浓度反应床与同轴一体化冷凝的闪蒸焦耳热ITO废料铟回收提纯方法及装置"专利技术交底书的配套可视化工具。

核心创新点聚焦于**装置结构**和**工艺方法**，而非难以落地的原位检测系统，以确保专利授权的可行性：

| 编号 | 创新点 | 类型 |
|------|--------|------|
| 1 | 梯度浓度反应床（底层高NH4Cl / 顶层高碳） | 结构创新 |
| 2 | 同轴一体化反应-冷凝腔（径向扩散原位冷凝） | 结构创新 |
| 3 | 两段式脉冲加热工艺（低温预氯化 + 高温闪蒸） | 工艺创新 |
| 4 | 多段梯度连续温控冷凝壁面（8段独立PID） | 结构+工艺创新 |
| 5 | XGBoost参数预测 + 贝叶斯自学习优化 | 方法创新 |

## 安装步骤

### 1. 安装 Python

前往 [python.org](https://www.python.org/downloads/) 下载并安装 Python。

> **重要**：安装时务必勾选 **"Add Python to PATH"** 选项。

### 2. 安装依赖库

打开命令行（CMD / PowerShell / Terminal），执行：

```bash
pip install xgboost scikit-learn gradio numpy pandas scipy matplotlib
```

如果提示 `pip` 不是内部命令，尝试：

```bash
python -m pip install xgboost scikit-learn gradio numpy pandas scipy matplotlib
```

### 3. 验证安装

```bash
python -c "import xgboost, gradio, numpy, pandas, matplotlib; print('OK')"
```

如果输出 `OK` 说明依赖安装成功。

## 界面功能说明

程序启动后共包含 **10个功能页**：

### Tab 1 - Parameter Prediction（参数预测）

- 输入ITO废料的4项成分参数：In2O3含量、SnO2含量、杂质含量、D50粒径
- 点击"Get Recommended Parameters"
- 输出：梯度反应床各层配料比例、两段式脉冲工艺参数、冷凝温区设计、预期回收率和纯度
- 同时生成脉冲温度曲线图

> **注意**：In2O3 + SnO2 + 杂质 的总和应约等于100%，否则会提示错误。

### Tab 2 - Gradient Bed（梯度反应床）

- 展示梯度浓度反应床的剖面结构示意图
- 标注三层（底层预氯化层、中层过渡层、顶层高温闪蒸层）的配料组成和功能
- 右侧标注各层温度区间和反应机理

### Tab 3 - Coaxial Chamber（同轴反应-冷凝腔）

- **Cross Section**（横截面）：展示同心圆结构——中心电极、反应床、环形蒸气通道、冷凝壁面、真空外壳
- **Longitudinal Section**（纵截面）：展示三层反应床、梯度冷凝壁面各温控段、热电偶位置、径向扩散路径

两个视图交替点击查看。

### Tab 4 - Pulse Curve（脉冲曲线）

- 可自定义两段脉冲的温度和时间参数
- 点击"Plot Curve"生成分段式脉冲温度曲线
- 曲线标注预氯化窗口和闪蒸挥发窗口

### Tab 5 - Condenser（冷凝系统）

- 输入操作压力（Pa），程序根据热力学模型计算各物质凝结温度
- 生成梯度温控冷凝壁面的温度分布曲线
- 标注各功能分区：固体颗粒拦截段、InCl3主沉积段、In金属沉积段、SnCl4收集段、冷阱段

> **关键参数**：在100 Pa下，InCl3与SnCl4的凝结温度差超过200 C，这是铟锡选择性分离的热力学基础。

### Tab 6 - Vapor Pressure（蒸气压曲线）

- 展示InCl3、SnCl4、SnCl2三种物质的蒸气压-温度关系（对数坐标）
- 标注常用操作压力线（100 Pa、500 Pa、1 atm）
- 可视化不同压力下的铟锡分离窗口

### Tab 7 - Process Flow（工艺流程图）

- 展示从原料预处理到最终产物的完整工艺流程
- 标注XGBoost参数预测和贝叶斯反馈优化的闭环路径
- 标注碳材料循环回收路径

### Tab 8 - Bayesian Flow（贝叶斯优化流程图）

- 展示"输入成分 -> 参数预测 -> 实验 -> 产物分析 -> 贝叶斯优化 -> 新实验建议"的自学习循环
- 说明模型随数据积累不断改善的机制

### Tab 9 - Bayesian Optimize（贝叶斯实验建议）

- 点击"Get Suggestion"获取贝叶斯优化模块推荐的下一组实验参数
- 数据不足5组时采用拉丁超立方探索
- 数据5组以上时切换为GP-Expected Improvement策略

### Tab 10 - Batch Records（批次记录）

- **提交实验结果**：完成实验后，输入实际工艺参数和回收率/纯度数据
- 点击"Save & Update Model"后，数据自动保存并触发模型重新训练
- **查看历史记录**：点击"Refresh"查看所有已提交的批次数据

> **使用建议**：每完成一组实验就及时提交结果，数据越多模型预测越准，贝叶斯优化推荐越精准。

```

          |
8. 重复 5-7 步，逐步收敛至最优工艺
```

## 注意事项

### 关于数据准确性

- 程序中的工艺参数预测基于合成数据预训练 + 历史实验数据增量学习
- **首次使用时**，预测结果仅作为参考，需通过实验验证
- 随着实验数据的积累，预测精度会逐步提升
- 预期回收率和纯度为模型估计值，不等于实际结果

### 关于热力学模型

- InCl3和SnCl4蒸气压模型采用Clausius-Clapeyron方程拟合
- 模型常数（A、B值）基于文献数据，实际体系中可能因物料组成、杂质等因素存在偏差
- 冷凝温区设计建议在热力学计算基础上预留 20-30 C 的安全裕量

### 关于梯度反应床

- 三层配料比例可通过参数预测模型自动计算，也可根据经验手动调整
- 层间铺设碳纸（约0.1mm厚）可有效防止层间过度混合，但不影响电流导通
- 装填时每层施加适当压力（0.5-5 MPa）压片，确保层间紧密接触

### 关于贝叶斯优化

- 建议至少积累5-10组实验数据后再依赖贝叶斯优化的推荐结果
- 初始阶段的拉丁超立方采样参数为随机生成，主要目的是探索参数空间
- 如果某次实验结果异常（如设备故障），不要将该数据提交到系统，否则会干扰模型

### 关于批次数据

- 批次历史数据存储在 `ito_ai_data/batch_history.json` 文件中
- 该文件为JSON格式，可手动备份或迁移
- 如果删除该文件，所有历史数据将丢失，模型将退化为仅基于合成数据的初始状态

### 关于Gradio界面

- 默认监听 `0.0.0.0:7860`，局域网内其他设备也可访问
- 如仅本机使用，可将代码中 `server_name="0.0.0.0"` 改为 `server_name="127.0.0.1"`
- 如需外网访问，可设置 `share=True`（会生成临时公网链接）

## 常见问题

**Q: 运行时提示 `ModuleNotFoundError: No module named 'xxx'`**

A: 说明缺少依赖库，执行 `pip install xxx` 安装对应模块。完整安装命令：
```bash
pip install xgboost scikit-learn gradio numpy pandas scipy matplotlib
```

**Q: 图表中的中文标签显示为方块或乱码**

A: 系统缺少中文字体。程序已内置SimHei和Microsoft YaHei字体的自动检测逻辑，如果仍然乱码：
- Windows系统通常自带Microsoft YaHei，一般不会有问题
- Linux系统可安装：`sudo apt install fonts-wqy-microhei`
- macOS系统一般自带中文字体，如仍有问题可安装：`brew install font-noto-sans-cjk`

**Q: 页面打不开或显示空白**

A: 检查命令行是否有报错信息。常见原因：
- 端口7860被占用：在代码中修改 `server_port=7860` 为其他端口号（如7861）
- 防火墙拦截：暂时关闭防火墙或添加7860端口例外

**Q: 预测结果和实际实验偏差很大怎么办**

A: 这是正常的。程序的预测模型基于合成数据预训练，需要通过Tab 10持续提交真实实验数据来校准模型。建议：
- 前5组实验重点关注参数空间覆盖，不要追求最优结果
- 实验数据达到10组以上后，预测精度会明显改善
- 结合Tab 9的贝叶斯建议进行系统性探索

**Q: 如何在不同电脑之间同步批次数据**

A: 复制 `ito_ai_data/batch_history.json` 文件到新电脑的相同目录下即可。该文件为纯JSON格式，跨平台兼容。
